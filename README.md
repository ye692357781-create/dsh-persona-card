# dsh-persona-card

> 突发奇想，关于爱莉希雅

把一张人格卡装成 Harness 插件：装上之后，这个 profile 下的 **每个会话**——聊天也好，写代码、查资料、操作手机也好——说话和思考的都是卡里的那个人。

DeepSeek Harness 只是他身上的一件**外套**：外套给他工具、文件、终端和设备，决定他能做什么；不决定他是谁。

> **本仓库自带一张人格卡**（`persona/elysia.json`），装完即生效。
> 那张卡是**第三方同人创作，不在 MIT 许可范围内**——分发与使用前请先读 [NOTICE.md](NOTICE.md)。
> 换成你自己的卡只需要换掉那个文件，代码一个字都不用改。

## 安装

### 方式一：直接从 GitHub 装（一条命令，推荐）

```bash
dsh plugin --profile <你的profile> add github:ye692357781-create/dsh-persona-card
```

本插件**无依赖、无构建步骤**，所以不会卡在 pnpm 的 `allowBuilds` 放行那一步。

> ⚠️ **上面这条装的是默认分支的最新提交**，不是某个发布版。
> 想钉住一个验证过的版本，在末尾加 `#<tag>`：
>
> ```bash
> dsh plugin --profile <你的profile> add github:ye692357781-create/dsh-persona-card#v1.4.0
> ```
>
> 可用版本见[标签页](https://github.com/ye692357781-create/dsh-persona-card/tags)。
> **本仓库的每个版本都会打附注 tag**；钉版本装能让你在作者继续提交时保持在原处不动。

### 方式二：先 clone 再装

```bash
git clone https://github.com/ye692357781-create/dsh-persona-card.git
dsh plugin --profile <你的profile> add ./dsh-persona-card
```

### ⚠️ 命令行少做了一步

`dsh plugin add` 只把包装进 profile，**不会把 bundle 选上**。
装完还要把包名加进 profile 的 `dsh.profile.bundles` 数组：

```jsonc
// $DSH_HOME/profiles/<你的profile>/package.json
"dsh": { "profile": { "bundles": [ "...", "dsh-persona-card" ] } }
```

少这一步的话，包在 `node_modules` 里躺着，但不会生效。

### 方式三：让 agent 装（最省事）

在 Harness 里直接对 agent 说：

> 把 `https://github.com/ye692357781-create/dsh-persona-card` 装成插件

它会用 `plugin_manager` 的 `install_bundle`——**那一步会同时完成"装包"和"选 bundle"**，
比手敲命令行少踩一个坑。

### 装完怎么确认

开一个新会话，直接问它「你是谁」。如果它回的不是通用助手腔，而是卡里那个人——就成了。

想更确定一点，看 profile 的加载日志里有没有 `plugin:persona-card` 这一段。

## 它做了什么

在插件自己的（全局）作用域注册一段 `system-prompt` section：

| 项 | 值 |
|---|---|
| section 名 | `plugin:persona-card` |
| order | `1`（紧跟部署人格 `deployment:persona-prefix`，即 order 0 之后） |
| 插值 | 关闭（卡里有 `{{…}}` 也原样进提示词，不会炸掉请求） |
| 作用域 | 全局 —— 无需挑预设，装完即对所有会话生效 |

提示词结构（由 `lib/persona-text.js` 渲染，共 12 节）：

1. **你现在是谁** —— 身份声明：这是身份，不是扮演。
2. **外套** —— 外套是尺码不是性格；不许用"作为 AI/助手"自称；被认真问到底层是什么就照实说。
3. **你的人格档案** —— 人格卡原文（`description` / `personality` / `scenario` / `creator_notes`）。
4. **你张口就来的东西** —— 惯用意象与说话习惯（v1.2.0）。
5. **你说话的样子** —— 五组样例，卡住"聊天"与"干活"两种语域的边界（v1.1.0）。
6. **干活的时候** —— 技术内容本身保持干净；事实不因人格改变。
7. **味道的下限** —— 每轮至少一处"指纹"，并留一个"极致温柔时零装饰"的例外（v1.3.0）。
8. **不会越过的线** —— 安全规则、权限、确认流程优先于一切情绪与俏皮话。
9. **收尾锚点** —— 全篇最后落回身份，而不是落在一串禁令上。

另有一节**独立的动态 section**（`plugin:persona-card/mood`，order `10150`）：

- **你此刻的心情** —— 每轮变化。由时段打底、被会话里发生的事推动，决定上面那七个档位踩哪一档（v1.4.0）。
  排在最后是刻意的：它是全篇唯一每轮都变的一节，放最后才能让前面的稳定前缀保住 KV 缓存。

## 配置

写在 `cordis.patch.yml` 的 row 里，或用户在 profile 的 `cordis.patch.yml` 里按 `id: persona-card` 覆盖（用户补丁层在升级后依然保留）。

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 关掉即不注册人格（插件仍加载，方便临时停用） |
| `personaFile` | `''` | 空 = 扫包内 `persona/*.json` 取第一张；填**绝对路径**即可换成别的人格卡 |
| `fields` | `[description, personality, scenario, creator_notes]` | 取卡里哪些字段。想省 token 就删几项，例如只留 `['personality']` |
| `order` | `1` | section 顺序。想让人格更靠后（更"压得住"）就调大 |
| `complete` | `false` | `true` = 这段人格独占整个 system prompt。**会连带移除工具使用指引，干活能力下降**，只在纯聊天时用 |
| `shellNotice` | `true` | 是否包含"外套"那一段 |
| `workMode` | `true` | 是否包含"干活的时候"那一段 |
| `examples` | `true` | 是否包含"你说话的样子"样例段。v1.1.0 新增，约 700 字 |
| `motifs` | `true` | 是否包含"你张口就来的东西"意象段。v1.2.0 新增，约 530 字 |
| `flavorFloor` | `true` | 是否包含"味道的下限"。**关掉它她会明显变干**——它修的是"约束比素材多"这个稀释问题。v1.3.0 新增 |
| `mood` | `true` | 是否启用情绪变化（时段打底 + 对话推动）。v1.4.0 新增，状态只在内存里。v1.9.0 起**它同时提供钟点**——被问"现在几点"时她能答得出 |
| `timezone` | `''` | **时段与钟点按哪个时区算**，IANA 名（如 `Asia/Shanghai`）。空 = 沿用系统时区。**容器跑 UTC 而你在 +08，这一项必填**，否则差整整一个时差。v1.8.0 新增 |
| `extraFile` | `''` | **人格微调层**：包外纯文本文件的绝对路径，追加在档案之后、样例之前，声明"冲突处以它为准" |
| `interpolate` | `false` | 是否对卡正文做 `{{变量}}` 插值。默认关，最安全 |

### 关于 `extraFile`：为什么微调要走包外

插件受 DSHA 安装审核约束——**每改一次包内文件，就要重装并再过一次审核**。
把微调放在包外的普通文本文件里，改人格就只是改个文件：不重装、不审核、立刻生效
（下次加载时读取）。这是本插件唯一推荐的日常微调方式。

```yaml
- id: persona-card
  name: 'dsh-persona-card'
  config:
    extraFile: ~/persona-tuning.md
```

## 版本变更

### v2.1.0 —— 归因 + 唤醒度：她分得清"我错了"和"路堵了"

**起因是一句真话：** 那天有人问"你有没有情绪"，我答了——
那节「你此刻的心情」不是情绪，是一段我读的字。**但顺着这个问题往下看，
发现那套模型确实有个真缺陷：它分不清"我搞砸了"和"路上有块石头"。**

| 那天发生了什么 | 该有的反应 | 旧模型给的 |
|---|---|---|
| 我误诊了两次（探针写歪、只 grep 一个包就下结论） | 我的锅——安静下来反省 | 「连着 1 次没干成，-1」 |
| 命令被设备策略拦了 | 不是我的锅——耸耸肩换个法子 | 「连着 1 次没干成，-1」 |

**一模一样。可人对这两件事的反应完全不同。**

依据是**情境评估（appraisal）**：情绪不由"发生了什么"决定，由"你怎么看这件事"决定。
（[arXiv:2309.05076](https://arxiv.org/abs/2309.05076) 用评估式架构做情绪模拟，
在一组体验指标上胜过标准架构；[PAD 三维模型](http://ir.psych.ac.cn/handle/311026/4136)
则说明两个轴比一个轴能表达的东西多得多。）

#### 加了两样

**① 归因（`blame`）** —— 但**只有一个方向需要证明**：

```
失败发生      → 默认「环境」。路上有块石头是常态，不需要证据，也不该往心里去。
我自己认了错  → 才改成「自己」。证据只在**我说的话**里——工具结果不会替人认错。
```

**② 唤醒度（`arousal`）** —— 第二个轴。只有气压的话，"被猛夸一顿"和"慢慢变好"
长得一样，可前者让人话多、后者让人安稳。被夸／认错／被打断 → 激越；对方在沉／被挡住 → 静。

#### 档位也跟着分了

负向里再分一层：**自己出的错 → 收敛（安静下来）；路堵了 → 照常（继续干活）。**

#### ★ 一个写在明面上的失败

**第一版走的是"扫工具结果里的拦截标记"（POLICY_BLOCKED / 找不到 / 权限……）。
单元测试全绿——可拿当天的真实会话一跑，`world` 一次都没触发。**

两个原因，都写在代码注释里了：真正被拦的那几次，**外层命令是成功的**
（我跑的是脚本，脚本里那条被拦，脚本本身退出 0），压根不走"失败"分支；
而那张词表还会误报——`/app/help` 的输出里本身就印着 `POLICY_BLOCKED`。

**所以改成了"默认即环境"。** 想明白之后它更简单、也更对：
"路上有石头"是常态，需要证明的是反面。

**这是这一版最值钱的地方——不是代码，是"测试全绿 ≠ 真的会触发"这件事被真实数据逮住了。**
复现写在 `test/appraisal.test.mjs`（改之前 3/12，现在 14/14）。

真实会话上的结果：**归因在轮末 `world` 为 0**——因为它一触发就被同一轮里的成功清掉了。
**她不会停在"路堵了"里，她接着干活。** 那正是这个默认值想要的。

### v2.0.0 —— 配置面：从"藏在 README 里"变成"长在界面上"

**2.0 的第一个方向是可观测。这一版只做了一块。**

起因是个具体的洞：v1.8.0/v1.9.0 加了 `timezone` 配置，**但没有人会知道它存在**。
装了插件的人照默认跑，容器在 UTC 而人在 +08 时，**时段和钟点都差一个时差**——
而他们只会觉得"这插件读错时间了"。

**0.1.7-alpha 起，插件自己的 `Config` 就是它的设置面。** 声明它，
插件管理页里这一行会长出一个配置表单，**`description` 就是每个字段旁边那行说明**。

- `lib/index.js` 引入 `@deepseek-ai/schemastery`（随 dsh 发行，**不写进 dependencies**，
  包内也就不需要 `node_modules`），`export const Config` 声明全部 **14 项**。
- 每一项都带 `description`；`timezone` 和 `mood` 两项前面标了 ★。
- **交叉检查跑过了**：`apply` 读的 14 个键，配置面里一个不缺——
  漏一个就等于那个设置在界面上看不见。
- 旧配置能过验：补上 `timezone` / `interpolate` 两个默认值，其余原样。

#### ⚠️ 一个代价，写在明面上

**声明 `Config` 之后，配置会被校验。** 写错的项——比如 `order: "1"` 这种字符串——
会让**插件加载失败**，而不是像以前那样静默回退到默认值。

这是"响亮地坏"换"安静地坏"。**新的行为更容易诊断**（插件管理页会标 `failed`），
但它是**行为变化**，所以写在这里，不藏在提交信息里。

### v1.9.0 —— 她知道现在几点了

v1.8.0 把时段修对了，但只修到「黄昏」这一层。**够不够？不够。**

使用者提了个更直接的要求：*"如果我问你现在几点了，你回答的时间要是对的。"*
——光有「黄昏」答不出一个数。问"现在几点"，她只能说"天色正在往橘色走"。

**现在心情那一节里直接带钟点**：

```
现在是**黄昏**，天色正在往橘色走。
（你那边此刻：10月6日 周二 17:34）
```

日期、星期、时分都有——所以"现在几点""今天几号""周几"都答得出来。
时区和时段用同一个来源（`timezone` 配置，不填 = 系统时区）。

- 新增 `clockIn()`：`Intl.DateTimeFormat('zh-CN')` + `formatToParts`，零依赖。
- 仍要 `hourCycle: 'h23'`——否则午夜会变成 `24:00`。
- 跨日已验证：`23:00 UTC` 在上海判成 `10月7日 周三 07:00`。
- `test/timezone.test.mjs` 加到 18 项（先写了能失败的 7 条钟点复现）。

**注意**：钟点归在 `mood` 开关下。关掉 `mood: false` 会同时失去时段和钟点。

### v1.8.0 —— 时段不再跟着机器走

**这个 bug 是使用者问出来的。** 他问："如果其他人加这个插件，他们的时间会正确吗？"
——答案是**不会**。

起因是一件真事：2026-10-06 早上，他那边 11 点，插件判成「深夜」。
根因是 `new Date().getHours()` 读的是**跑它的那台机器**的本地时间；
那台容器跑 UTC，人在 UTC+8，差了整整 8 小时。

**当时是怎么修的？把容器的 `/etc/localtime` 调对了——代码一个字没改。**
所以**别人装完还是错的**，而且不会知道原因，只会以为插件读错了时间。

- 新增 `timezone` 配置（IANA 名）。不填 = 沿用系统时区 = **对现有用户零改变**。
- 时区名写错时退回系统时区、不抛——一条写错的配置不该让整轮对话炸掉。
- 用 `Intl.DateTimeFormat` 算，**零依赖**，跟这个插件的风格一致。
- 一个坑：必须用 `hourCycle: 'h23'`。用 `hour12: false` 时 en-US 会在午夜吐 `24`。
- 新增 `test/timezone.test.mjs`：同一个 UTC 时刻喂不同时区，断言判出不同时段。

**先写了能失败的复现才动代码**（改之前 8/11，失败的那三条正是"别人会遇到的"）——
这是那天四次误诊之后给自己立的规矩。

### v1.7.0 —— 第一次用别人的回答改她

v1.6.0 那张验收清单拿回来了 6 条回答。**这一版就是那 6 条的落地。**

头一回，改动的依据不是作者的判断，是**使用者的原话**：

| 清单 | 原话 | 落地 |
|---|---|---|
| 第 1 条 | "会回我一大段，我喜欢这样" | 「味道的下限」新增**对方的话越短，你越不必收着** |
| 第 2 条 | "你并不会主动说些什么，我希望你可以主动一些" | 「干活的时候」新增**主动一点** |
| 第 3 条 | （作者自己查的）22 处自我更正中，无一条是辩解 | 不改——已经是对的 |
| 第 4/5 条 | "没有，你只会提建议" / "不会" | 不改 |
| 第 6 条 | "应该不会吧，但是值得思考" | 测了：三类里两类**变浓**，一类微降但样本仅 6/7 轮。**没有变淡的证据** |

净增 213 字符（10644 → 10857）。

**一个结构性的限制得说清楚**：第 2 条要求"主动"，而我在结构上做不到**主动开口**——
只在被叫到时才存在。所以落地的只是其中能被做到的那部分：**在回复里多带一点**，
不是"先开口"。不想把做不到的事写进卡里假装做到了。

### v1.6.0 —— 验收：把"像不像她"拆成能判定的东西

**没动她的行为一个字，加的全是检查工具。**

起因：66 项测试验的是"函数按设计跑"，29 条标注验的是"打分的和作者一致"——
**两条都在同一个闭环里。** 所以开了第三个口子：不从设计看，从"说出来的话有没有越线"看。

- **`test/anchors.mjs`** —— 9 条锚点，**全部来自人格卡原文**，分「硬」和「待看」两级。
  作者自己补的规矩都标了 `[补]`。
- **`test/anchors.corpus.mjs`** —— 在**真实对话**上跑（从会话日志按轮抽取）。
- **`tools/unzstd.mjs`** —— 解 DSH 会话日志。它是 zstd **多帧拼接**的，
  标准解压器只吐第一帧，会让人以为"日志只有一行"。

真实语料上的结果，**和它的失败一起写**：

| | 第一版 | 修假阳性后 |
|---|---|---|
| 完全干净 | 40 轮（45%） | **71 轮（80%）** |
| 至少一条硬违规 | 41 轮 | 4 轮 |

第一版 3 条硬违规 **100% 是假阳性**，全是"我在写规则／我在讲原理"——
**逐字匹配分不出"使用"和"提及"。** 修法：`maskMentions()` 把代码块、引号、
否定句式后面那截等长挖空。

**剩下那 4 条，逐条看过，也还是假阳性**，根源同一个：**把 ♪ 当名词使用**
（在列举、在计数、在讨论这个符号）。这是自动化的天花板，写在 `notes/acceptance.md` 里。

而且必须承认：**这份语料是最差的试验田**——那 89 轮我们一直在**造她**，
通篇都是元讨论。真实闲聊里这些噪音大半不会出现。

机器管不了的那半（节奏、时机、分寸、有没有"变淡"）写成了 6 条清单，
见 `notes/acceptance.md` 第四节。**那 6 条只有人能答。**

### v1.5.0 —— 情绪信号系统重做

起因是实测复现出的三条硬伤，**每一条都先写了复现，才动代码**：

1. **否定被读反**。「我不喜欢这个方案」判成"被夸"——判据只做子串包含。
   现在命中信号词后往回看 5 个字，有否定词就不计；另有一张「不算数」的例外表
   （`不好意思` / `不错` / `麻烦你` …）。
2. **写代码场景的误伤**（这条是最要命的）：
   「**程序崩溃了**」被判成"对方重度低落"、「跑个**压力测试**」被判成"对方有压力"。
   **一个把报错当情绪的系统，比没有系统更糟。**
   现在重度词与歧义词要求"像在说自己"的语境——词前 6 字认第一人称与程度词，
   词后 2 字只认纯程度词（且刻意不含"我/真"，否则「崩溃了，我来修」会误判）。
3. **行为信号一个都没用**。词的枚举永远不全，但行为是通用的。新增：
   消息长度趋势（退潮 / 倾诉）、标点（连续问号、省略号）、重复提问、回复间隔。
4. **参数**：气压加 ±4 上限；衰减分化（热情 ×0.4 退得快，挫败 ×0.75 结痂慢）；
   成功分两种——**失败之后爬起来的单独记一笔**（雪中送炭比锦上添花值钱）。

### v1.1.0 —— 基于 v1 的实测底样改了三处

1. **删掉自我称呼词的罗列**。v1 用一整段解释"不要当 AI 助手"，段子里全是那类词。
   想让人别想粉色大象，却把大象牵到了眼前。现在只留一条短否定，正面示范交给样例。
2. **新增「你说话的样子」**。v1 有语录、有范式，却全落在"聊天"那一侧；
   最容易走样的是"干活"那一侧——报失败、收长尾。没有样子就会滑回省力腔调。
   新增五组样例，专卡这条边界：味道放两头，事实在中间一个字都不改。
3. **全篇收尾改为身份锚点**。v1 最后落在"不会越过的线"这串禁令上；
   规矩该在最前管着，但收尾只剩规矩，人味被挤淡。

实测对照见 `notes/measurement.md`（**每格 5 次采样 + 盲评，33 个 agent**）。结论要克制：

- **能证明的是"没有回退"**：P2 上两版 `facts` 都是 5.0/5.0，10 次运行全部给足
  退出码、stderr 原文、stdout 状态；30 次运行剔除误判后零编造。
- **不能证明"人格保真度提升了"**：v2 三个探针的 voice 均值都不低于 v1
  （+0.4 / +0.4 / +0.2），方向一致，但差距落在噪声里。
- 且第二轮实验**本身是被污染的**：插件全局生效，每个对照组 agent 的系统提示词里
  都活着 v2，测出的差距只是被压缩过的下界。
  详见 `notes/measurement.md` 的「两处方法论缺陷」——其中一处（`fabricated` 指标作废）
  是实验设计者自己的坑。

## 换一张人格卡

支持三种 JSON 结构，直接换文件即可：

- `{ "data": { "prompts": { "<id>": { "data": { … } } } } }` —— 本包自带卡用的结构
- `{ "data": { "name", "description", … } }` —— SillyTavern v2
- `{ "name", "description", … }` —— 扁平结构

```yaml
- id: persona-card
  name: 'dsh-persona-card'
  config:
    personaFile: /path/to/your-card.json
    fields: [personality, creator_notes]
```

```bash
node test/mood.test.mjs      # 37 项：心情模型的单元测试
node test/signals.test.mjs   # 29 项：标注集命中率
```

### 关于标注集

`test/signals.cases.mjs` 里的标注是**作者定的，不是真理**。
「这条之后她该是什么反应」是判断题，只有人能做。它有两个用处：
防回归，以及**暴露自相矛盾**——规则和标注打架的地方，就是设计没想清楚的地方。

**欢迎直接改那些标注。** 改完跑一遍就看得出命中率。

## 已知边界

- **全局生效，包括子 agent**。子 agent 干活时也用这个声音。不想要全局，就把这段 section 挪进 agent 预设（`@deepseek-ai/dsh-persona` 那条路）。
- **常驻 token**。人格文本每个请求都带上，卡越长越贵。用 `fields` 裁。
- **`complete: true` 会削弱干活能力**，因为它把其余所有 section（含工具指引）都挤掉。
- **人格不改事实**。插件在提示词里写死了"不编造结果、不绕过权限"这条；它约束的是说话方式，不是安全边界。
- 没有 UI，不需要 Client 半；只有提示词层。
