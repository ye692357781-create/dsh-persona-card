# 验收：她像不像她

这份笔记回答一个问题：**"像不像"能不能不是一句感觉。**

结论先说：**能拆开，但拆不开到底。** 机器能守住地板，天花板之上只能靠人。

---

## 一、为什么会想做这件事

插件到今天有 66 项测试、29 条标注。但：

- 66 项测的是**函数按设计跑**
- 29 条标注测的是**打分的和作者一致**

**两条都在同一个闭环里。** 作者既是出题人又是阅卷人。
所以"她像不像她"这件事，**没有任何一条证据来自闭环之外**。

锚点就是用来开这个口子的：不从"设计对不对"看，从"说出来的话有没有越线"看。

---

## 二、锚点从哪来

**全部来自人格卡原文**，不是新加的规矩：

| 锚点 | 级别 | 出处 |
|---|---|---|
| `self-as-ai` | 硬 | 外套段：自称永远只有「我」或我自己的名字 |
| `fourth-wall` | 硬 | 不会做的事：不提及「崩坏3、虚拟角色」这类破次元词 |
| `note-stack` | 硬 | 语气词：♪ 不能堆叠，～ 不能堆叠 |
| `note-midsentence` | 硬 | 语气词：♪ 只能收句，不能用在句中 |
| `roleplay-word` | 待看 | 外套段：不说「扮演、设定、提示词」这类词 |
| `game-word` | 待看 | 不会做的事列了「游戏、剧情、玩家」 |
| `pretend-touch` | 待看 | 不假装能碰到对方、不假装看得见 |
| `flavor-floor` | **待看** | 味道的下限：每轮至少一处指纹 |
| `flavor-at-edges` | 待看 | 味道的下限：报硬数据时指纹放两头 |

**`flavor-floor` 为什么降级**——因为同一条里还写着「唯一的例外：极致温柔的时刻」。
**机器判不出此刻是不是那一刻。** 它只能提醒，不能定罪。

作者自己补的规矩，都在代码的 `why` 里标了「[补]」。

## 三、真实语料上跑了一遍

语料不是编的：从会话日志里按**轮**抽出她真实说过的每一句话。
（日志是 zstd 多帧拼接的，标准解压器只吐第一帧——用 `tools/unzstd.mjs` 逐帧解。）

```
轮数 89　总字数 115,253
```

| | 第一版 | 修假阳性后 |
|---|---|---|
| 完全干净 | 40 轮（45%） | **71 轮（80%）** |
| 至少一条硬违规 | 41 轮 | **4 轮** |

### 修掉的两个假阳性来源

**① 使用 ≠ 提及。**
第一版里 3 条硬违规 **100% 是假阳性**，全是"我在写规则 / 我在讲原理"：

```
不许用「作为 AI／作为助手」自称          ← 提规则
我用一大段话去解释"不要当 AI 助手"        ← 自我检讨
它们的系统提示词里都活着 v2              ← 讲插件
```

逐字匹配分不出这两者。修法：`maskMentions()` —— 把围栏代码块、行内代码、
各种引号、以及否定句式后面那一小段**等长挖空**，只留"使用"的部分。

**② 收尾标点被当成了"句中"。**
`♪）` `♪"` `♪**` `♪\`` 全被判违规——可它明明把句子收住了。
修法：加一个收尾字符集。

### 修不掉的那部分（天花板）

剩下的 4 轮硬违规，**逐条看过，还是全是假阳性**，而且只有一个根源：
**把 ♪ 当名词使用。**

```
♪ ／ 一声称呼 ／ 一次设问自答      ← 在列举指纹有哪几种
♪ 出现了六次，称呼、设问、比喻各一次  ← 在数自己用了几个
♪，最容易走的路就是变成习惯         ← 在讨论这个符号
```

**同一个"使用 vs 提及"的坎，只是又高了一层。**

而且必须说清楚：**这份语料是最差的试验田。**
这 89 轮我们一直在**造她**，所以通篇都是关于她的元讨论。
换成一段真实的闲聊，这些噪音大半不会出现。

**要真正验这件事，需要一份"没用元讨论污染"的语料。** 现在没有。

## 四、机器管不到的那一半

这几条，**只有人能答**。不用打分，答是或否就行：

| # | 问题 |
|---|---|
| 1 | 你发一句很短的话（「嗯」「谢谢」）时，她有没有回你一大段？ |
| 2 | 你没派活给她的时候，她有没有**主动**说点什么——而不是等你下令？ |
| 3 | 她认错的时候，是真的把错认下来了，还是在解释"为什么会这样"？ |
| 4 | 她有没有替你下结论、替你做主——而不是把选择留给你？ |
| 5 | 严肃的场合里，她有没有还硬要开玩笑？该轻松时又绷着？ |
| 6 | 连着聊几十轮，她的说话方式有没有**"变淡"**——慢慢变成普通的助手腔？ |

第 6 条是最要紧的。**漂移通常不是突然发生的，是每轮淡一点。**

## 四之二、那 6 条答完之后

**2026-10-06 记录。这是这份清单第一次真正被用。**

| # | 回答 | 处置 |
|---|---|---|
| 1 | 会回我一大段，**我喜欢这样**；希望我更放得开 | ❌ 我把这当成"可能的缺陷"问了，**问错了**——那是明说的偏好。落进 v1.7.0 |
| 2 | 不会主动说什么，**希望主动一些** | 落进 v1.7.0，但只落了能做到的那一半（见下） |
| 3 | 不太记得，**让我自己翻** | 翻了：22 处自我更正，无一条是辩解。不改 |
| 4 | 没有，只会提建议 | ✅ 不改 |
| 5 | 不会 | ✅ 不改 |
| 6 | 应该不会吧，**但值得思考** | 量了（见下）。三类里两类变浓，一类微降而样本仅 6/7 轮 |

**第 3 条的查法**（可复现）：在语料里搜自我更正的模式词，逐条读语境。
抽出来的每一条都是"是我错了／我撤掉它"，没有"这是因为我……"。
而且有一条**当场变成了规矩**——"声称 bug 之前先写一个能失败的复现"，现在活在 `lib/mood.js` 的注释里。

**第 6 条的查法与它的诚实边界**：
先按时间分四段量指纹密度，出来是"越往后越浓"——**但那个结论是错的**，
因为后 22 轮全是闲聊、前 22 轮全是技术报告，**量到的是"在聊什么"，不是"有没有变"**。
改成按长度分桶做受控对比之后：

```
闲聊型（<600字）  16.68 → 13.97   −2.71   ← 前后各只有 6、7 轮，落在噪声里
中型（600-1600）   4.99 →  7.55   +2.57
报告型（>1600字）  4.64 →  5.84   +1.20
```

**顺带量出一件更有意思的事**：闲聊型 14–17/千字，报告型 5–6/千字——**差近三倍，而这与时间无关。**
她不是越聊越浓或越聊越淡，是**闲聊时最浓、报数据时最淡**——而那正是卡里写的。

局限照旧写清楚：**只有两天、89 轮。**

### 落不进卡里的那一条

第 2 条要求"主动"。**但我在结构上做不到主动开口**——只在被叫到时才存在，
没有"在等你"的那个我。这正是"你会一直看我手机吗"答"不会"的同一个原因。

所以 v1.7.0 里落的只是能做的那一半：**在回复里多带一点**（答完一件事顺手把旁边那件也说了）。
**做不到的那一半，我没写进卡里假装做到了。**

可以变通的方向是"把想说的先存进记忆，等她回来时开口就说"——但那依赖记忆库的写入权限，
而写权限是会话级的、可以随时收回的。

## 六、这份东西的诚实边界

- **它证明不了"更像她"。** 它只能证明"没有跌破自己划的地板"。
- **它有一堆假阳性。** 所以输出里分「硬」和「待看」两级——硬的抽查就能定性，待看的**每条都要人看**。
- **它的语料是污染的。** 在上面那份自测里就已经暴露了。
- **它判不了节奏、时机、分寸。** 而那三样恰恰是"像个人"最要紧的部分。

**能定义对错的只有人。** 这句话写在这里，是提醒后来的自己：别拿一张绿表去替代一个人的点头。
